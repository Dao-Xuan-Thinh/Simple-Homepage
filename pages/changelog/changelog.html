All notable changes to the homepage dashboard.

Batch 8 — Skins, expandable cards, 7-day history Latest 2026-07-25
  • uiFive selectable skins — Bento (asymmetric tile wall, hero panels), Ops (monitoring rig, titled panels over ruled plot areas), CRT (amber phosphor terminal with scanlines), Paper (editorial print, serif and hairlines) and Classic. From the ◐ button in the header or the command palette; each has light and dark and the choice sticks across reloads. They're prototypes: pick one and the rest get deleted
  • uiSkins change the form the graphs take, not just their colour — filled area, bare stroke, discrete columns, or block characters rendered as text. Switching skin redraws every chart
  • uiDensity, radius, borders, sheen and typography moved out of the component rules into CSS variables, so each skin layers its structural redesign on a shared token base instead of forking the stylesheet
  • featClick any stat card for the full graph over 30m / 6h / 24h, with current/peak/avg/min, live detail, and the alerts recorded in that window. Keyboard-reachable (Tab, then Enter)
  • featHistory is now persisted for 7 days as 5-minute min/avg/max buckets in history.json, so the long windows survive a server restart. The bucketed charts draw the min–max band behind the average
  • featDisk fill projection — a least-squares fit over the history gives percent-per-day drift and an estimate of when the volume hits 95%. Says "collecting" rather than inventing a number under a day of data
  • featService outages are logged alongside the metric alerts — the 30 s health probe feeds the same episode machinery, opening after 2 consecutive failed checks and closing on recovery
  • featSparklines added for swap, load and disk, plus a mirrored network graph — download above the baseline, upload below, on a shared scale
  • apiGET /api/history serves two tiers and reports which via res: fine ~20 s samples for windows up to an hour, 5-minute buckets beyond. Network throughput (net_rx/net_tx) added to the sample
  • fixSwap now alerts on absolute GB, not percentage. macOS resizes its swapfiles on demand, so used/total is a sawtooth that sits in a 50–90% band by design — the same ~1.5 GB of swap read as 94% one day and 50% the next, purely because the total grew from 2 GB to 3 GB. It had fired six false criticals. Now swap_gb, warn 4 GB / crit 8 GB; the percentage is still graphed
  • fixAlert hysteresis is per-rule and in the metric's own units. The old flat margin of 5 would have given a 4 GB threshold a close point of −1, so a swap episode could never have cleared
  • fixPersisted state is loaded before the background threads start — load_alerts() clears the list, which could have wiped an outage recorded by the status loop in the first seconds after boot

Batch 5 — Live temperature & memory fix (macmon) 2026-07-13
  • featLive CPU/GPU temperature via macmon — reads Apple Silicon sensors through the private IOReport API with no sudo, so the M4 finally shows a real °C instead of just a pressure level
  • fixMemory stat was internally inconsistent (bar used one psutil formula, the GB text another) — now sourced from macmon so the % and the GB always agree and match Activity Monitor
  • featPower/Energy now uses macmon's measured sys_power instead of the idle-base estimate — and no longer needs the sudo powermetrics rule
  • api/api/stats adds gpu_temp; temp is now populated on Apple Silicon and thermal_pressure is null on the macmon path
  • uiThermal card shows GPU temp beside the CPU reading; Power card drops the "est." qualifier now that the figure is measured
  • fixGraceful fallback when macmon is absent — thermal-pressure level, psutil memory (made consistent), and a flat energy base
Batch 4 — Disk fix, power/energy & more stats 2026-07-09

  • featNew Load Average (1/5/15-min + core count), Network Total (GB since boot), and Docker (running / total containers) cards
  • featNew Storage Volumes card — per-volume usage bars for the internal drive and any external drives (e.g. a backup drive), with APFS system volumes filtered out

  • uiEnergy label is honest — powermetrics only measures chip power, so the total is an estimate (idle base + SoC), not a metered wall reading
